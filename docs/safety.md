# 安全说明

真实机器人执行必须谨慎、逐步推进。

## 真实动作前检查

- 确认机器人周围无人员。
- 确认地面稳定、不打滑。
- 确认急停和遥控器可用。
- 确认只连接目标机器人。
- 确认没有真实 group-control 任务在运行。
- 确认 RobotState 稳定后再发送命令。
- 真实动作前必须先 dry-run。

## 开发顺序

建议顺序：

```text
dry-run
单机器人
单机器人稳定性检查
双机器人 dry-run
双机器人真实验证
更大规模群组 dry-run
更大规模群组真实验证
```

## 机器人隔离

任何真实群控前，先分别验证 `Robot_A` 和 `Robot_B`。单台机器人离线不能造成其他机器人进入不安全状态。

## 网络异常处理

如果出现 RobotState timeout、丢包、重复包或 100 ms 级 gap：

- 停止后续真实动作
- 保留日志
- 检查有线链路
- 检查 `jy_exe`
- 检查配置
- 不要第一时间修改 watchdog、增益或控制周期

## 基线验证阶段禁止

- 未完成单机验证就执行真实双机器人群控
- 使用未经验证的动作参数
- 通过修改 `kp`、`kd`、控制周期或 watchdog 掩盖通信问题
- 在人员靠近时执行真实动作
- 提交密码、token、SSH key 或机器人私有凭证
